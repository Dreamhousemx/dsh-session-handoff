## 1. 第 1 部分：配置卡渲染

### 1.1 入口

1. 打开设置。
2. **期望**：左侧导航里有一项 **「会话交接」**，位置在「插件」之后（`order: 18`），
   不在插件详情页里面。

> 这是本插件有意注册的独立 `settings.section`，不是 `plugins.row.config` 那一格。
> **如果导航里没有，先分清是哪种原因**：
> - 12:32 那次桌面端启动的日志里，失败的 3 个条目是 `dsh-rewind-plugin`、
>   `dsh-codex-subscription`、`dsh-connect-workbuddy` —— **不含本插件**，但说明这套
>   组合的客户端模块加载本身不稳。客户端模块一旦出错，同页其它条目可能一起不出现。
> - 12:29 更早的一次失败才是本插件：`pending (waiting for service: forms)`，
>   那个问题已在 20:59 那轮修掉（客户端现在只注入 `slots`）。若今天又看到
>   `waiting for service: forms`，说明跑的还是旧构建。

### 1.2 卡片骨架

| 检查点 | 期望 |
| --- | --- |
| 卡片根节点 | DOM 上有 `data-dsh-plugin="dsh-session-handoff"`、`data-dsh-surface="settings-modal"` |
| 字段行 | 每行 `data-dsh-part="field"`，左侧标签宽 132px，右侧控件，下面一行灰色小字说明 |
| 主题 | 颜色全部走 `--dsw-alias-*`；切亮/暗主题后文字与边框仍可读，不出现「白底白字」 |
| 报错 | 页面上**不应**出现 `✕ 未能读取已保存的配置…` 或 `✕ 设置文档不可用…` |

### 1.3 字段与期望值（关键：对数字）

| 行标签 | 控件 | 期望值 | 判定 |
| --- | --- | --- | --- |
| 自动交接 | switch + 文字 | 关，右侧文字 **「仅手动 /handoff」** |  |
| 触发方式 | 3 个 radio | 选中 **「上下文占用率」** |  |
| 上下文占用达到 | range 1–100 | 滑到 **40**，右侧数字 **`40%`** |  |
| 累计消费达到 | number | **`2000000`**（原样数字，不做 2M 缩写） |  |
| 自动压缩 | switch + number + 「% 时原地压缩」 | 关；数字 **`70`**，且该数字输入框**灰掉**（未开启压缩时禁用） |  |
| 高级设置 | 折叠按钮 | 默认显示 **`▸ 高级设置`**（收起态） |  |

> **「40%」是最强的一条判别信号**：卡片读的是已保存配置，40 是 profile 里存的，
> 85 是代码默认值。如果看到 **85%**，说明读配置失败、页面回落到了默认值 —— 这是
> 缺陷，不是显示问题。

### 1.4 高级设置（点开）

点「▸ 高级设置」→ 变成「▾ 高级设置」，展开后逐项对：

| 行标签 | 期望值 |
| --- | --- |
| 评估间隔（毫秒） | `5000` |
| 占用率滞回（百分点） | `10` |
| 累计重臂（token） | `200000` |
| 单会话动作上限 | `3` |
| 简报输出上限 | `4096` |
| 等待边界超时（毫秒） | `900000` |
| 动作总时限（毫秒） | `1800000` |
| 迁移后自动跳转 | 开 |
| 交接后归档旧会话 | **关**（profile 里是 `false`） |

### 1.5 状态块

展开后底部有 `data-dsh-part="status"` 的浅底方块，四行：

| 行 | 期望 |
| --- | --- |
| 标题行 | 左「状态」，右 `idle`（忙碌时追加 `· 进行中`，闩锁时追加 `· 已设闩锁`） |
| 上下文占用 | 右侧百分比；下方 `70.0k / 1.00M · 精确`（数字会随会话增长而变，**「精确/估算」标注必须存在**） |
| 累计消费 | 右侧 `3.50M`；下方 `阈值未启用`（因为自动交接是关的） |
| 自动动作 | `自动动作 0/3` |

> 打开设置页时如果当前没有会话，状态块整块不显示，改为一行灰字
> 「当前没有打开中的会话，因此没有实时占用率可显示…」—— 这是**正确行为**，不是缺陷。

### 1.6 交互校验（三条，不用真交接）

1. **硬规则**：打开「自动交接」，再打开「自动压缩」，把压缩阈值设成 ≥ 交接阈值（例如都设 40）。
   - 期望：按钮下方出现红色 `✕ 压缩阈值必须低于交接阈值，否则压缩刚结束就会立刻触发交接。`
   - 期望：**「保存设置」按钮变为禁用**。
   - 改回 30 → 红字消失、保存按钮恢复可用。
2. **低阈值警告**：保持自动交接开，把阈值拉到 15%。
   - 期望：出现黄色 `⚠ 阈值低于 20%：会话可能发几条消息就被交接…`。
3. **保存往返**：把阈值改成一个新值（如 45）→ 点「保存设置」→ 关闭设置页再打开。
   - 期望：仍显示 45（真的落盘了），且没有报错红字。
   - 命令行可交叉验证：`~/.dsh/profiles/desktop/cordis.patch.yml` 里
     `autoHandoffAtContextPercent` 变成 45。
   - **测完请改回 40**，与本次基线一致。

> 其实这条的**写入链路已由命令行证明**（见 0 节最后两行：改 45 落盘、读回 45、改回 40
> 后字节一致）。页面上这一步只需确认**表单 UI 到 POST 这一段**也通 —— 即点了保存之后
> 重开页面仍是你填的值、且没有红字。这会顺带验证 `saveSettings` 的取值没有漏字段。

### 1.7 按钮状态

| 按钮 | 期望 |
| --- | --- |
| 立即迁移 / 取消 / 重试 | 有活动会话时可点；无会话时置灰（`liveSessionId()` 为 undefined） |
| 保存设置 | 主按钮样式（实心强调色）；无阻塞时可用 |

> ⚠️ 这三个按钮是**真动作**。这一步只需要看它们「亮/灰」是否符合上表，不要点。

## 2. 第 2 部分：一次真实完整交接

### 2.1 准备

1. 在同工作区新开一个会话（内容随意，比如发一句「记录：验收用临时会话」）。
2. 在这个**临时会话**里做下面的操作。

### 2.2 命令层（不换会话，先验小的）

| 输入 | 期望输出 |
| --- | --- |
| `/handoff bogus` | `未知子命令「bogus」。可用：/handoff、/handoff status、/handoff cancel、/handoff retry。` |
| `/handoff cancel` | `当前没有进行中的动作，无需取消。` |
| `/handoff status` | 六行起步：`## 会话交接状态` / `- 阶段：idle` / `- 上下文占用：… · x% · 精确` / `- 累计消费：…（日志投影）` / `- 自动交接阈值：未启用（仅手动）` / `- 自动压缩阈值：未启用` / `- 本会话自动动作：0 / 3` |

> 命令与输出**不应**出现在模型可见的对话历史里。

### 2.3 真交接

在临时会话里输入 `/handoff`。

**期望 A —— 原会话这一侧**
- 出现 `交接完成：新会话 session-… 已接手。`
- 下一行 `原会话处理完毕（日志保留，可回看）。`（因为 `archiveSourceAfterHandoff: false`，
  旧会话不会被归档，日志仍可回看）
- 再往下是逐项继承清单，标签只允许三种：**已继承 / 回退 / 未继承（附原因）**。
  应有这几项：`cwd`、`preset`、工作区、模型、权限、Plan 模式。
- 原会话此后不再接受新 turn（这是设计行为，不是卡死）。
- 交接**不应**打断当时正在跑的步骤；turn 应在 Step 边界以 blocked 收尾。

**期望 B —— 新会话这一侧**
- 浏览器自动切到新会话（`openNewSessionOnHandoff: true`）。
- 新会话第一条消息就是九段简报，标题 `# 会话交接简报`，依次：
  `会话事实` → `总体目标` → `约束` → `已完成` → `当前进度` → `已改文件` →
  `关键决策` → `已知问题` → `未完成` → `下一步` → `交接附注`。
- `会话事实` 段必须写对：工作目录、原会话 id、已完成 turn 数、上下文占用、累计消费。
- 新会话继承：同 cwd、同工作区、同 preset、同模型、同权限档、同 Plan 模式。
- 简报里**不应**出现真实密钥/令牌；若命中脱敏，`交接附注` 会写
  「简报中有 N 类敏感信息已被替换为占位符」。

**期望 C —— 失败时也不说谎（可选，时间充裕再做）**
- 在空白会话（没发过任何消息）里 `/handoff` → 应被拒绝：
  `当前没有可迁移的活动会话（空白会话不会被交接）。`
- 故意制造失败后，原会话应立即可继续，`/handoff retry` 可用。

### 2.4 交接后回查

1. 新会话里 `/handoff status` → 阶段 `idle`、占用率是**新会话自己的**数（应该很小）。
2. 旧会话里 `/handoff status` → 若已停止，应能明确看出不再接受输入，而不是静默无响应。

## 3. 回传方式

任选其一：

- 截图（设置卡整页 + 高级设置展开 + 交接完成后的两条消息）；
- 或把每项「通过/不通过 + 实际看到的内容」贴回来。

**特别留意这四类问题**，它们是目前代码里最可能出偏差的地方：

1. 卡片显示 **85%** 而不是 40% → 读配置失败回落默认。
2. 状态块显示「状态通道不可用」而当前确实开着会话 → 轮询 key 不对。
3. 导航里根本没有「会话交接」→ 客户端半没激活（可能被别的插件拖垮）。
4. 「保存设置」保存后重开变回旧值 → 写的是 `include:` 命名空间而不是行 id。
