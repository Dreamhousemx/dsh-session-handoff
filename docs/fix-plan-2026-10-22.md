## T0 —— 修正 `projectedTokens` 读取（P0）

**目标：** 让度量口径真正与输入框一致，且不依赖宿主未公开的 wire view。

**做法：** 不再读 `state.projectedTokens`，改为**按宿主的同一公式从原始 state 自行推导**。这样既不依赖 `snapshot()`（该 API 未在 `contracts.ts` 声明），也与宿主算法逐字对齐。

### 改动 1：`src/measure.ts`

`readPressureProjection()`（约 `:69-104`）内替换取值逻辑：

```ts
const pressure = typeof record.pressureTokens === 'number' ? record.pressureTokens : undefined
const surface = typeof record.surfaceTokens === 'number' ? record.surfaceTokens : undefined
const sampled = typeof record.sampledSurfaceTokens === 'number' ? record.sampledSurfaceTokens : undefined

// 宿主 wire view 的同一公式：
// projectedTokens = max(0, pressureTokens + surfaceTokens - sampledSurfaceTokens)
const projected =
  pressure !== undefined && surface !== undefined && sampled !== undefined
    ? Math.max(0, pressure + surface - sampled)
    : undefined

const used = projected ?? pressure
```

分级保持现状（`projected === undefined ? 'usage' : 'estimated'`），语义现在才真正成立。

同时更新该函数上方注释：说明 state 里没有 `projectedTokens`，是我们按 wire 公式推导的（附宿主出处），避免下一个人再踩。

### 改动 2：`tests/unit/measure.spec.ts`

- 把 `pressure()` 辅助函数改名为 `projectionState()`，并在注释里写明**它必须模拟 `stateOf()` 的原始 state 形状**。
- 删除所有往 state 里塞 `projectedTokens` 的用例，改为给 `pressureTokens + surfaceTokens + sampledSurfaceTokens` 三元组，断言推导出的 `used`。
- **新增一条防回归用例**：state 里只给 `pressureTokens` 与 `contextWindow`、不给 `surfaceTokens`/`sampledSurfaceTokens` → 断言 `used === pressureTokens`、`baseline === 'usage'`、`quality === 'exact'`。
- **新增一条形状守卫用例**：显式断言「即使 state 里混入 `projectedTokens`，也不应影响结果」——防止将来有人又依赖 wire 字段。

### 验收

- 用真实会话跑 `/handoff status`，百分比与输入框一致（误差 ≤1%），`source` 为 `contextPressure`。
- 有 `projectedTokens` 语义的会话标 `估算`，纯 `pressureTokens` 的标 `精确`。

## T5 —— 程序检测「原会话末尾可能仍在等用户」（I-1 第二层）

**目标：** 把「是否在等用户」从模型叙述变成程序事实，写入**模型不可篡改**的会话事实块。

### 改动 1：`src/session-summary.ts`

新增类型与读取函数：

```ts
export interface PendingInput {
  readonly kind: 'question' | 'unanswered-assistant'
  readonly detail?: string
}

/**
 * 判定原会话结束时是否可能有未答复的输入。
 *
 * 两个来源，优先级从确定到推测：
 * 1. `userQuestions` 投影的 active 非空 —— 系统已登记的未答复提问，确定。
 * 2. 末尾 surface 事件是 assistant/message —— 只是"最后说话的是助手"，
 *    不足以断定它在提问，措辞必须保守。
 */
export function readPendingInput(
  session: SessionLike | undefined,
  projections: SessionProjectionsLike | undefined,
): PendingInput | undefined
```

实现要点：

- 投影分支：`stateOf(session, 'userQuestions')` 的 state 形状是 `{ inheritedEventCount, timed, questions: { active, settled } }`（注意 active 在 `state.questions` 下，不是 state 顶层）。`active.length > 0` 时返回 `{ kind: 'question', detail: 前 3 个问题文本自 active[].questions[].question }`。任何异常一律 `undefined`（不能让检测失败拖垮交接）。
- 事件分支：倒序扫描 `sessionEvents(session)`，跳过非 surface 事件，取第一条 `user/message` / `assistant/message` / `tool/result`；若为 `assistant/message` 返回 `{ kind: 'unanswered-assistant' }`。

把结果挂进 `SessionFacts`，新增可选字段 `readonly pendingInput?: PendingInput`。

### 改动 2：`src/index.ts`

`summarize`（`:177`）里 `readSessionFacts` 之后补一行：

```ts
facts = { ...facts, pendingInput: readPendingInput(session, services.sessionProjections) }
```

注意顺序：必须在 `withObservedServices` 之前或之后都行，但不要覆盖它已填的 `permissionPreset` / `planMode`（用展开而非重建）。

### 改动 3：`src/session-summary.ts` 的 `renderBrief` factsBlock

在「已完成 turn」行后插入（仅当 `pendingInput` 存在时）：

- `kind === 'question'`：
  `- ⚠ 未答复提问：${detail}（程序检测，原会话结束时系统仍登记为未答复）`
- `kind === 'unanswered-assistant'`：
  `- ⚠ 原会话末尾：最后一条是助手发言，其后没有用户消息——可能仍在等用户回话，交接未必等于获准执行「下一步」`

**措辞要求：** 第二种必须用「可能」「未必等于获准」，不得断言「有未决问题」——用不确定的措辞陈述确定的事实，而不是用确定的措辞陈述猜测。

### 验收

- 构造 `userQuestions.active` 非空的会话 → 简报出现第一行。
- 构造末条为 `assistant/message` 的会话 → 出现第二行且含「可能」字样。
- 无投影注册（`stateOf` 返回 undefined）→ 不抛错，退化为事件判断。
